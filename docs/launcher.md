# Запуск приложений и DCC


Два варианта запуска
1. Запуск приложения в контексте воркспейса
2. Запуск agio команды через интерпретатор приложения в контексте воркспейса и API приложения

## Пример команды запуска приложения

Этот способ запускает приложение с помощью core интерпретатора. Например, обычное открытие для работы или выполнение python скрипта

```shell
agio -w [WORKSPACE ID] launch --app [APP-NAME]/[APP-VERSION]/[APP-MODE] -- [APP-ARGS]
```

Здесь запускается приложение в контексте воркспейса и передаётся список аргументов приложение после `--`.
Сначала создается venv-воркспейс обычный, чтобы подтянуть аддоны приложения.
Потом launch создает venv под приложение и в нём запускает приложение. 

Пример

```shell
agio -w [WSID] launch --app maya/2024/python --task-id UUID  -- my-custom-script.py
agio -w [WSID] launch --app-name houdini --app-version 21.1.111 --env KEY=VALUE --task-id UUID -- myscene.hip
```


## Пример запуска команды через интерпретатор приложения

Этот способ позволяет выполнять agio-команды с помощью окружения определенного приложения.
Обязательно требуется Python-интерпретатор у приложения который можно запускать отдельно!

```shell
agio -w [WORKSPACE ID] --app [APPNAME/APPVERSION] [CMD] [ARGS]
```

Пример - публикация из софта

```shell
agio -w [WSID] --app houdini/21.0.111 pub .../scene.hip
```

`agio` - точка входа, глобальный agio энвайромент

`-w [WSID]` - определение контекста исполнения

`--app houdini/21.0.111` - интерпретатор какого приложения используем. Режим указывать не нужно, всегда используется `python`

`pub` - agio-команда

`.../scene.hip` - обычные аргументы команды


## App Mode

- `default`: обычный запуск с UI
- `python`: запуск стендалон python-интерпретатора от DCC. Должно поддерживаться в DCC
- `venv`: опционально альтернативный python-интерпретатор для создания venv под dcc. по умолчанию используется `python`

## Режимы запуска

Команда `agio launch` использует ровно один из трёх режимов старта:

- **replace** (по умолчанию): текущий процесс заменяется приложением (`os.execve`).
  Всё работает в текущей консоли с сохранением PID. Так работает запуск из терминала,
  в том числе после переключения воркспейса через `agio -w <WSID>`.
- **new_console**: приложение открывается в отдельной консоли. Консоль живёт, пока работает
  приложение, и транслирует его stdout. Консоль отслеживает всё дерево процессов приложения:
  DCC-приложения (например houdini) порождают отсоединённый UI-процесс (`fork` + `setsid`) и
  завершают стартовый процесс, поэтому консоль закрывается только после завершения последнего
  процесса приложения (`agio/tools/process_supervisor.py`, PR_SET_CHILD_SUBREAPER).
  С флагом `--keep-console` (`-k`) консоль не закрывается при ошибке (non-zero exit code),
  чтобы можно было прочитать сообщение.
- **detached** (`-d`): фоновый процесс без консоли, вывод скрыт.

Запуск через action (broker, HTTP `/action`):

- `keep_console: true` — broker открывает одну отдельную консоль для команды `agio action ...`.
  Вся цепочка (переключение воркспейса → `agio launch` → приложение) выполняется в ней через
  replace. Консоль закрывается вместе с приложением, а при ошибке остаётся открытой.
- `keep_console: false` — приложение стартует как скрытый detached-процесс без консоли.
